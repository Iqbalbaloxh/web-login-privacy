Privacy Policy

Last updated: November 9, 2026 · Operator: Mr Aftab · Contact: supprot@legendsmmpanel.com

1. Who we are and scope

This Privacy Policy explains the data handling of web login, a desktop-oriented Facebook login and URL research utility operated by Mr Aftab. It applies to use of the application and communications about it. This policy is not a policy of Meta or Facebook; web login is an independent project and is not endorsed by Meta.

2. Information processed

Based on the current developer-provided Python implementation, the application may process:

  • Facebook account identifier and name obtained after authentication, where available.
  • Facebook authentication access tokens and session cookies used by the current legacy implementation.
  • The Facebook email/ID and password typed into the legacy login form, transmitted for a login attempt. The supplied code does not intentionally save the password to a file, but sends it to a Facebook endpoint. This legacy authentication method is not the official Facebook Login SDK and should be replaced before public release.
  • Page/profile URLs supplied in target TXT files and publicly accessible video and Reel permalinks returned by accessible services.
  • Local diagnostic messages, request results and progress/status.

Access to public data may still be subject to privacy, platform, intellectual-property and legal restrictions. No private profile access is implied.

3. Purpose and use

Data is used to attempt authorized sign-in, retrieve publicly accessible or otherwise permitted video URL references, save per-target text exports, display status and diagnose errors. We do not claim permission to obtain private content or circumvent access controls.

4. Storage, location and retention

In the supplied Python version, the application stores the access token in .token.txt and session cookies in .cookie.txt in its working directory, and saves extracted URLs in the local FB_VAULT_LINKS directory. The example code writes those credential files as plain text, without encryption. Target lists remain in the input file selected by the user. Data stays on the device unless the user backs it up, synchronizes the folder, shares output, or another program transfers it. No separate developer-controlled cloud database is evident from the code reviewed.

These local files are not automatically deleted on a fixed schedule by the supplied version. They remain until the device owner deletes them or removes the application directory. The application makes requests to Facebook/Meta services, which process the relevant requests under their own terms.

5. Cookies, access tokens and security

Authentication tokens and cookies grant access and must be protected. The legacy implementation writes credentials in readable local files. Users should keep the files private, avoid backups/shared directories that expose them, and revoke sessions if the device is lost or compromised. We cannot promise encryption, cloud isolation, secure deletion, or zero risk where those features are not present in the code. We recommend replacing legacy password collection and private authentication with supported Facebook Login before offering the app to third parties.

6. Disclosure and third parties

The current implementation sends authentication and content requests to Meta/Facebook services. It does not show any separate developer-hosted analytics, advertising network, or third-party data broker. This statement describes the provided version only; the policy must be revised before any new integrations, hosted databases, advertising or sharing practices are introduced. The developer does not sell users' personal data as part of the described application.

7. Legal basis and data subjects

Where applicable law requires a legal basis, processing may rely on a user's request to operate the tool, consent to optional authorization, compliance with law, or legitimate interests where those apply. Publicly visible account information may still be personal data. Users must use the application in accordance with applicable law and platform policies.

8. Your choices and rights

Depending on applicable law, you may request access, correction, deletion or information about data processed about you. Contact supprot@legendsmmpanel.com. You may also revoke the app's access through Facebook settings where the app is listed. Revoking permission does not erase files already exported on a local computer.

9. Deleting data

For local data, delete .token.txt, .cookie.txt, target TXT files and the FB_VAULT_LINKS directory from the relevant computer. This removes the local copies within those paths; backups and synchronized copies must be deleted separately. See our Data Deletion Instructions. To request deletion of any data held directly by the developer, email the contact address. We will assess the request and reply in line with applicable obligations. We do not claim the developer can remotely delete files solely held on your device.

10. Children, changes and contact

The application is not intended for children below the age permitted by applicable law. We will update this policy if data handling changes. Privacy questions, requests and complaints may be emailed to supprot@legendsmmpanel.com. Operator: Mr Aftab. Date: November 9, 2026.
